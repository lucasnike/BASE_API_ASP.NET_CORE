Visão Geral da Base.API

Bem-vindo à documentação interativa da **Base.API**. Esta aplicação fornece uma visão geral da arquitetura, padrões e instruções operacionais para o desenvolvimento e manutenção do projeto.

O projeto é construído sobre o **ASP.NET Core 10.0** e utiliza padrões modernos como Mediator (CQRS), Injeção de Dependência automática e validação com FluentValidation. Use o menu ao lado para navegar pelas seções e encontrar rapidamente os comandos, exemplos de código e diretrizes que você precisa.

🚀 Configuração do Banco de Dados

A API utiliza **Entity Framework Core** com Migrations para o gerenciamento do esquema do banco de dados. Esta seção contém os comandos essenciais do `dotnet ef` que você usará para criar e aplicar migrações.

Criar uma nova Migration

Use este comando para gerar uma nova migração (ex: "Initial") após modificar seus modelos de dados.

dotnet ef migrations add Initial -p .\\Infra.Data -s .\\Web.API

Aplicar Migrations ao Banco

Use este comando para aplicar todas as migrações pendentes ao banco de dados configurado.

dotnet ef database update -p .\\Infra.Data -s .\\Web.API

🏗 Arquitetura e Padrões

Esta seção detalha os principais padrões de arquitetura usados no projeto. Entender esses conceitos é crucial para manter a consistência e a separação de responsabilidades (SoC) do código.

Padrão Mediator (CQRS)

O projeto utiliza o padrão Mediator para desacoplar os componentes. A regra de ouro é: **Nenhuma lógica de negócio deve residir nos `Controllers`**. Eles apenas recebem requisições e enviam Comandos ou Consultas.

Fluxo de Requisição

Controller
→
Mediator
→
Command/Query Handler

Camadas de Dados e Negócio

A lógica é separada da seguinte forma:

  • Repositories: Criados exclusivamente para acesso a dados (consultas, inserções, etc.).
  • Services: Criados para encapsular regras de negócio complexas que podem ser reutilizadas por diferentes Handlers.

Injeção de Dependência (DI) Automática

Para simplificar a configuração, o sistema registra serviços e repositórios automaticamente. Para que isso funcione, suas classes devem seguir duas regras:

1. Visibilidade

As classes devem ser `public`.

2. Interfaces Marcadoras

Serviços devem implementar `IService`.

Repositórios devem implementar `IRepository`.

⚙️ Configuração e Segredos (AWS)

A aplicação integra-se com o **AWS Secrets Manager** para gestão segura de configurações, como strings de conexão e chaves de API. O sistema injeta os segredos automaticamente no `IConfiguration`.

Configuração no `appsettings.json`

Para ativar, basta definir o nome do seu segredo da AWS na chave `ApiSecretName`:

"ApiSecretName": "nome-do-seu-segredo-na-aws"

Os valores serão carregados em `Application:Secrets`.

✅ Validação (FluentValidation)

A validação de dados de entrada (Commands e Queries) é feita utilizando **FluentValidation**. Isso mantém os modelos de dados limpos e centraliza as regras de validação.

Como Criar um Validador

Crie uma classe que herde de `AbstractValidator`, onde `T` é o seu Command ou Query, e defina as regras no construtor.

public class CreateUserCommandValidator : AbstractValidator
{
    public CreateUserCommandValidator()
    {
        RuleFor(x => x.Email).NotEmpty().EmailAddress();
        RuleFor(x => x.Password).MinimumLength(8);
    }
}

🏥 Operações e Logs

Esta seção cobre o monitoramento da saúde da aplicação e o registro de logs, essenciais para ambientes de produção.

/api/health

Logging

O sistema suporta logs em Console, Arquivo e Banco de Dados. Para registrar logs, basta injetar `ILogger` em qualquer classe (Serviço, Handler, etc.) e usar os métodos de log.

public class MeuServico : IService
{
    private readonly ILogger _logger;

    public MeuServico(ILogger logger)
    {
        _logger = logger;
    }

    public void Processar()
    {
        _logger.LogInformation("Processamento iniciado.");
        try
        {
            // ... lógica ...
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Erro ao processar.");
        }
    }
}
